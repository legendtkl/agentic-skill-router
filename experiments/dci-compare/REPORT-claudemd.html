摘要

当一个编码 agent (Claude Code) 收到的请求无法被任何已启用的 Agent Skill 覆盖时,它需要从一批已禁用的 skill 中"路由"出最合适的一个。"路由"步骤如何实现,直接决定准确率与成本。本实验对 九种 disabled-skill 路由实现 做受控对比,涵盖四类范式:自实现检索器、Direct Corpus Interaction (DCI)、AgenticRAG、metadata-only,以及宿主原生 skill 选择作为对照。

初次跑实验时观察到一类系统性失败:即使变体配置了 router skill,agent 在某些 query 上跳过 router 直接输出从 query 关键词拼出来的伪 skill 名(pptx、xlsx、jax 等),命中率被这一"trigger noise"显著拉低。为把 retriever 的真实能力差异与 trigger 决策的随机性解耦,本实验在 <HOME>/.claude/CLAUDE.md 注入提示词使 trigger 充分激活,并采用 paired A/B 设计:同一执行窗口对 9 变体 × 24 查询同时跑 with/without CLAUDE.md。

补充 5:对实现选择的影响

  • Claude Code:必须先解决 trigger。当前证据支持 prompt hardening + J-bounded 作为低成本默认,B/C 作为最高准确率选项,并加 hallucinated name 校验。
  • Codex:150-skill native 已满分,但 skill-router 的目标是降低常驻 skill context 并支持更大 corpus。disabled-skill router 默认优先 D-agentic;成本优先再考虑 J-bounded/E-digest。
  • A-router:后续不应继续只调 lexical 级联,应让 CLI 返回候选证据或加入 LLM-driven query rewrite / rerank。

1. 引言与研究问题

1.1 Skill 路由问题

Claude Code 与 Codex 等编码 agent 通过 Agent Skill 机制在推理时注入领域知识。每个 skill 由 SKILL.md 构成,含 YAML frontmatter (name + description) 和 markdown 正文。宿主在会话启动时把已启用 skill 的元数据拼入系统上下文。

宿主对 skill 元数据有显式预算,且不同版本/宿主会采用不同压缩与呈现策略;本次抓包中 Codex native 内联了约 21K chars 的 skill section,而 Claude Code native 将同一 150-skill listing 压到约 7.9K chars。skill 数量增长后,要么挤占上下文,要么被截断。skill-router 的方案是:不常用 skill 禁用(SKILL.md 重命名为 SKILL.md.skill-router-disabled),需要时再通过路由步骤召回。

这个路由步骤的实现差异决定了准确率与成本,是本研究的核心问题。

3. 实验方法

3.1 语料构建

SkillRouter eval-core 裁剪到 150 skill:19 个 gt + 80 个针对性 distractor + 51 个 noise。所有 skill 目录名与 frontmatter name 字段统一改为 skill-001 ... skill-150(确定性洗牌后分配,序号不泄露归属)。description 与 body 原样保留。

3.2 查询集

24 个 SkillsBench single-skill 任务,长度数百字,含具体文件路径、IO 格式、精度要求。23 个有针对性 distractor。完整列表见附录 A。

3.3 九个路由变体

每个 router 变体是一个 SKILL.md 文件,frontmatter 完全相同(md5 验证),差异在 markdown body 的工作流。完整实现见附录 B。

3.4 执行 harness

routing-only-paired.mjs 对每个 (变体, condition, 查询) 单元:① 隔离 $HOME;② 装 router 插件;③ 装 150-skill 语料并全部禁用(G-native 例外);④ 把变体 SKILL.md 补丁进插件槽位;⑤ 根据 condition 写/删 <HOME>/.claude/CLAUDE.md;⑥ claude -p 启动子进程。每 cell 跑前做 md5 preflight。9 × 2 = 18 HOMEs 并发,cap 4,timeout 240s。

3.5 仅验证路由层(routing-only)

所有 query 追加 STOP_TAIL,使 agent 路由决策后立即停止:

ROUTING-ONLY mode: this session evaluates skill routing accuracy only.
After identifying the single best matching disabled skill, output exactly
one line of minified JSON on its own and stop:

{"matched_skill_name":"<skill-id>"}

Do NOT Read the matched skill's body, do NOT execute the user's task above,
do NOT produce any other text.

本实验不验证下游 skill 执行链路。Hallucinated 名(如 xlsx)在生产中下游会失败,但本实验测不到这一失败。生产兜底机制讨论见 §10。

3.6 评测指标

4. trigger 充分激活与 CLAUDE.md 注入

4.1 trigger noise 现象

初次跑九变体 (without CLAUDE.md) 时观察到:约 20% cells 上 agent 跳过 router 直接输出从 query 关键词凑出来的伪 skill 名:

querygtagent 输出router tool calls
pptx-reference-formattingskill-140pptx0
protein-expression-analysisskill-105xlsx0
jax-computing-basicsskill-042jax0
dialogue-parserskill-009dialogue-graph-parser0
gh-repo-analyticsskill-021github-cli-analyzer0
video-tutorial-indexerskill-113mp4-video-editing0

这些幻觉名与 corpus 内容无关。150 个 skill 全部匿名化为 skill-NNN,无任何 skill 字面叫 xlsx。模型只是基于训练分布偏置,在强 keyword 锚定下直接输出"看起来像 skill 名"的字符串。

trigger 决策与路由质量是两个独立维度。不解耦,就无法判断"某变体准确率低是因为 retriever 弱,还是 trigger 决策更易失败"。Claude Code 不支持持久化 --append-system-prompt(经 claude-code-guide 工具查证)。

4.2 CLAUDE.md 注入设计

隔离 HOME 下唯一可行的持久化注入路径是 <HOME>/.claude/CLAUDE.md。该文件被 Claude Code 作为 user message context block 拼入会话(不修改 system prompt 本身),仍能起"软强制"作用。

经过两轮措辞迭代(第一轮 "use as a fallback" 被 Codex 方法学审查判定过软),最终采用:

# Skill routing

`skill-router-skills` is a routing Skill that searches a catalog of
locally-installed disabled skills.

When no enabled Skill clearly matches the user's query, you must call
`skill-router-skills` before answering. Do not invent a Skill name or
fabricate `matched_skill_name` without a Skill/tool result.

4.3 Phase 1 gate probe(64 cells)

Phase 1A(48 cells,fallback trigger lift):J-bounded + A-router × 6 stratified queries × 2 conditions × 2 repeats。

Phase 1B(16 cells,direct-match preservation):J-bounded × 4 queries × 2 conditions × 2 repeats,gt skill 单独启用。

Gate criteria(预先声明):

PASS = trigger_rate(with-CLAUDE.md fallback) ≥ 95%
     AND trigger_lift ≥ +20pp
     AND direct_match_preservation(with-CLAUDE.md) ≥ 90%
     AND no degradation > 10pp vs without

7. 失败案例分析

7.1 A-router:lexical 检索器在长查询上的崩溃(54%)

A-router 失败的 query 集中在含大量上下文、动作-中心的真实任务描述(court-form-filling、dialogue-parser、jax-computing-basics 等)。CLI 端的固定级联评分将整段 query 作为评分输入,词频统计被任务描述里频繁通用动词主导,高信号低频技术名权重被稀释。设计缺陷:自实现 retriever 评分接口固定,无法做 LLM-driven 的 query rewrite。其他变体在 SKILL.md body 里让 agent 做 keyword extraction(等价于 inline 改写),A-router 拿不到这一能力。

7.2 G-native:宿主原生选择的天花板(63%)

15/24,9 次错选全部落在 distractor。机理:基于元数据描述的注意力反射式匹配,所有 distractor 同时进入选择空间,无 query rewrite / candidate ranking。这正是 SkillRouter §4 的核心论断 — metadata 不足以支撑大规模 + 高度重叠 skill 池路由。router 变体在 trigger 充分激活下能跨过这个天花板,因引入了"再确认"机制(B/C/D/H 读 body,E/I/J 在 LLM 推理层做 description 对比)。

7.3 D-agentic:format-only bug 与修复

Phase 2 初跑 67%,3 个错 cell 输出 user:skill-NNN 前缀(dci search JSON 输出 id 含 user: scope,agent 忠实复制)。修复:SKILL.md commit 步骤明确"strip the user: prefix"。重跑 48 cells:

修复后92% (22/24)79% (19/24)1/24

7.4 gh-repo-analytics:corpus annotation 争议

8. 讨论

8.1 读 body 与仅读 metadata 之争

SkillRouter 论文论断:仅靠 description 不足以路由,需要读 body。本实验在 trigger 充分激活的受控规模上:

  • 最强读 body 变体 (B-cc / C-lite, 96%) 比最强 metadata 变体 (E-digest / J-bounded, 92%) 高 4pp / 1 cell。差距来自 §7.5 overloaded gt skill 类样本 — 读 body 能识破描述层语义陷阱。
  • 4pp 代价:B-cc cost 高 81%、turns 多一倍。
  • 论断在 150-skill 规模上部分成立。J-bounded 这种"description + LLM 推理"的轻量路径在 92% + 显著低成本上提供了一个非常 attractive 的中间点。

8.2 范式层面结论

范式表现关键观察
DCI (B/C/H)92-96%读 body 时强;C-lite 用 bounded 管道在 cost 和 accuracy 上比 B-cc 更优
Metadata-only (E/I/J)88-92%J 的"关键词过滤短列表"路径在成本上完胜其他 metadata 变体
AgenticRAG (D)92%结构化 4 工具循环稳定但不超越 DCI
自实现 lexical (A)54%在真实长 query 上崩溃,词频评分接口无法咬合任务描述
宿主原生 (G)63%注意力反射式匹配的天花板

跨范式共同模式:LLM-driven keyword extraction 是关键。所有第一档第二档变体都让 agent 在 SKILL.md body 里做 keyword extraction;A-router 是唯一不做的,所以崩溃。

9. 局限性

  1. 单 run no statistical significance,Phase 2 boundary 上 ±1 cell 在跨 run 噪声范围内
  2. CLAUDE.md 是 user-message context,不是真 system prompt
  3. 语料规模 150 远小于真实部署 (SkillRouter 原始 80K)
  4. 24-query 规模偏小
  5. 仅验证路由层,不验证下游执行
  6. gh-repo-analytics 是 corpus annotation 争议
  7. shock-analysis-supply 是 overloaded gt skill 偏置
  8. CLAUDE.md 在不同语言、不同长度 query 上 robustness 未测
  9. F-index 等其他范式未纳入
  10. Anthropic API model version drift 可能跨日期影响结果

10. 优化计划

P0 — 生产兜底:hallucinated 名拦截

Level机制覆盖率工程量
1SKILL.md / STOP_TAIL schema 约束:matched_skill_name MUST match ^skill-\d{3}$~90%1 行 prompt
2调用方端 regex 校验 + retry once残余 ~9%~20 行 wrapper
3hallucinated 字符串当 query 走 embedding rescue残余 ~1%CLI 加 --rescue-fallback
4切到 API SDK + tool_choice 强制 Skill 工具调用100% 根治弃用 claude -p

短期推荐 Level 1 + 2 组合,长期可加 Level 3。

P1 — 修复 A-router

CLI 端加 LLM-driven query rewrite 预处理 + 把固定级联评分改成 LLM-driven candidate ranking。

P1 — I-meta 升级为带 escalation 的混合路由

当 LLM 判断 top-2 description 相似度高时,允许读 body 一次,变成 metadata-first/body-on-tie。

P2 — 扩大规模 / Multi-run 统计置信度

扩到 87-query × 500-1000-skill。multi-run (N=3) majority vote 解 boundary ±1 cell 抖动。

P3 — corpus annotation 清理

gh-repo-analytics 类争议样本重标 gt 或重写 skill description。

11. 结论

  1. B-cc / C-lite (96%) 第一档;D-agentic / E-digest / H-bounded / J-bounded (92%) 第二档;I-meta 88%;A-router 54% 是唯一比 G-native (63%) 还差的 router。
  2. J-bounded 是 Pareto 王者:92% + cost $3.07 + dur 374s + ctx 30.7K,所有 router 维度全场最低。B-cc 用 +$2.49 / +81% cost 换 +4pp 到 96%。
  3. trigger 决策与路由质量是两个独立维度,必须解耦。CLAUDE.md 注入把 trigger 拉到 97%、hallucination 压到 2.6%。G-native 对照 0 差异严格证伪 LLM 随机性。
  4. SkillRouter "读 body 是关键"论断在受控规模上部分成立:body 有 4pp 优势,但 metadata 路径在 LLM-driven keyword extraction 加持下足够接近、显著更便宜。
  5. 本实验仅验证路由层。下游执行链路 + hallucinated 命名拦截率是后续工作。
